# Project Instructions

## Purpose

This repository contains an assessment application that evaluates an employee's skill level within their current role. The application conducts dynamic role-relevant questionnaires generated by an AI agent, tracks context across assessment sessions, and evaluates whether the employee's skills are below, meeting, or exceeding expectations for their role tier.

## Tech Stack

- **Frontend:** React, TypeScript, Tailwind CSS
- **Backend:** Python, FastAPI, Pydantic, SQLModel / SQLAlchemy
- **AI / LLM Integration:** Python OpenAI / Anthropic SDKs (Structured Outputs)
- **Database:** PostgreSQL

## Development Principles

- **Understand First:** Analyze existing components, types, and API contracts before making modifications.
- **Simplicity:** Prefer simple, explicit solutions over unnecessary abstractions.
- **Reusability:** Reuse existing UI components, custom hooks, and shared TypeScript interfaces.
- **Type Safety:** Ensure strict typing on both the TypeScript frontend and Pydantic schemas on the backend.
- **Minimal Dependencies:** Do not add frontend npm packages or Python libraries without clear justification.

## Frontend Rules

- **Design System:** Use standard Tailwind utility classes and existing base components.
- **State Management:** Keep assessment session state synchronized with the backend.
- **Accessibility & Responsiveness:** Follow WCAG accessibility standards and ensure mobile-friendly layouts.

## Backend & AI Guidelines

- **Structured LLM Output:** Always enforce strict schema output (Pydantic) for LLM responses (questions, evaluations, feedback).
- **Context Preservation:** Ensure all previous QA pairs in a session are included in the prompt context sent to the evaluation agent.
- **Data Privacy:** Never hardcode secrets, API keys, or personally identifiable employee information (PII).

## Definition of Done

A feature is complete when:
1. The requested behavior is fully implemented end-to-end.
2. Frontend TypeScript types match backend Pydantic schemas.
3. Existing features remain unbroken and relevant tests pass.
4. Code conforms to project formatting and safety guidelines.
